# Establish document ownership

During setup, locate the repository management root from project instructions and existing owners; use Git top-level only when no project boundary is established. Working in a subproject does not silently create another management root. Resolve recorded paths from that root, while Markdown links remain relative to their files.

Inspect current project instructions, document conventions, representative artifacts and work tracking. Record the agreed document types, owners, new locations and historical exceptions in the project's existing document entry, normally `docs/AGENTS.md`. Use [docs-agents.md](docs-agents.md) as a starting point when no owner exists. A standalone `artifacts.md` is not required and must not be created as a second registry. If a project already uses one as an owner, preserve that routing until an authorized consolidation is complete.

For each artifact, identify its authoritative owner: the tracker owns work status, review and approval evidence; the work item owns its delivery scope, product behavior and acceptance; an independent Spec may own a behavior contract that stays effective across work items. In projects selecting Agent Notes as the design owner, Notes own durable technical proposals, decisions, alternatives and rationale; do not create a separate RFC or ADR for the same decision. Register which existing independent Specs, RFCs and ADRs remain current and which are historical; an old file or `accepted` status alone does not confer future authority. A root `CONTEXT-MAP.md` can direct readers to context-local documents; the Notes root config separately selects record directories. Contexts do not create record categories.

Review existing and new work separately. Preserve an existing artifact's authority until a change of ownership is authorized; the old file may remain at its path as historical evidence afterward. Register a location for a new independent Spec or design document only when its continuing ownership is needed; do not register `docs/specs/`, `docs/design/` or `docs/adr/` by default or create empty files. If ownership changes, record the old and new owners, affected scope, any still-effective decisions needing a current owner, status mapping and link repair. Registration alone does not migrate content or silently keep historical decisions in force.

Verify that root and subproject readers reach the same document ownership entry, every active artifact has one owner, historical paths remain discoverable, and tracker approval and delivery status are distinct. Refer to the tracker and Notes rules from the document entry instead of repeating their mechanics there.
