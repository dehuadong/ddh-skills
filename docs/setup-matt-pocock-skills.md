# setup-matt-pocock-skills 使用指南

`setup-matt-pocock-skills` 为目标项目配置工程技能需要的跟踪器、文档归属和领域资料入口。本文提供调用方式和可复制的需求提示词；实际配置流程以 [setup 技能](../skills/user-invoked/setup-matt-pocock-skills/SKILL.md) 为准。

## 调用前准备

在目标项目中调用已安装的完整技能目录，保留其支持文件及 `resources/`。安装和选配见 [技能目录](../skills/README.md)。目标项目与技能资源所在仓库可以不同；setup 应先确认目标项目的管理根目录。

调用时写清这次要配置哪些能力、已经确定的选择，以及允许修改的范围。常见配置如下：

| 配置范围 | 需要说明或确认的内容 |
| --- | --- |
| 工作跟踪 | GitHub、GitLab、本地 Markdown 或其他系统；工作项位置、状态、评审与批准证据 |
| 文档归属 | 哪类内容由谁拥有、新工作写到哪里、规则入口在哪里 |
| 领域资料 | 单上下文或多个上下文；已有术语表、边界和资料位置 |
| Agent Notes | 现有或新的安装位置、记录分类；多个上下文时选择记录范围与公共区 |
| Triage | 选用或已安装 triage 时，复用或确定标签映射 |

已有选择直接提供或让 setup 从项目配置读取。未决的重要选择会在配置差异摘要中提出；已授权且选择明确的配置可继续更新。只配置部分技能时，范围也应明确。

术语表统一使用 `GLOSSARY.md`，映射文件使用 `GLOSSARY-MAP.md`。调用 setup 时，默认将管理根的旧 `CONTEXT-MAP.md` 更名为 `GLOSSARY-MAP.md`，将管理根及已登记上下文中的旧术语表 `CONTEXT.md` 更名为同目录下的 `GLOSSARY.md`，保留内容并修正活动引用及映射中的链接。此项文件名迁移也适用于重复调用，除非用户明确排除。任一组新旧文件同时存在且内容不同，保留两份并先解决内容归属冲突；不将无关的同名文件纳入迁移。

## 新项目：首次配置

下面示例选择本地 Markdown 工作项和 Agent Notes，可将跟踪器改为实际使用的系统。

```text
/setup-matt-pocock-skills

请为当前新项目配置 Planning、Implementation 所需的工作跟踪、文档归属和领域资料入口，采用本地 Markdown 工作项及 Agent Notes。

先检查项目指令和已有配置，确定仓库管理根目录。已有充分配置直接复用。展示配置差异；在选择明确且本次授权的范围内完成配置，未决的重要选择集中列出。

- 工作项使用 .scratch/<feature>/proposal.md；登记状态以及评审、批准证据的记录规则。
- 工作项拥有本次范围、产品行为与验收，并链接相关 Agent Note。
- 长期技术提案、设计、决定、真实备选和理由由 Agent Notes 拥有。
- 在项目文档入口登记 Notes 的实际位置、记录范围及格式/生命周期规则入口，即使暂时没有记录。
- 独立 RFC/ADR 对新工作未启用，其内容归 Agent Notes；不预建 docs/design/ 或 docs/adr/。
- 独立 Spec 按跨工作项行为合同的需要启用，先登记属主和位置，再创建正文；不预建 docs/specs/。
- 单上下文项目登记 GLOSSARY.md 的用途，术语表在需要时建立。若发现多个上下文，先提出边界与路径供选择，再分别确认 Notes 记录范围和是否需要公共区。
- Notes 分类按本项目实际内容确定，不复制技能库的项目分类；首份记录前必须具备适用分类。

保留项目定制，按需合并配置。管理规则和工具按所选范围部署，记录目录在首份记录需要时创建。

最后检查首份工作项和技术决定能否从配置找到写入位置，运行适用检查，报告修改、复用项及未决事项。保留现有工程推进规则，本次配置不授权产品规划、实现或远程发布。
```

新项目不创建空 `docs/adr/`，仍应在文档归属中说明架构决定归 Agent Notes。已启用类型有明确位置和规则入口；未启用类型有内容去向；按需类型有首次启用前的登记要求。具体配置示例见 [docs-agents.md 的项目归属配置](../skills/user-invoked/setup-matt-pocock-skills/docs-agents.md#项目归属配置)。

## 已有项目：补齐配置

只想接入技能或修复缺口时，使用下面的提示词。它保留已经登记的当前属主；历史归档和权威切换使用下一节的专门请求。

```text
/setup-matt-pocock-skills

请检查当前项目中 Planning、Implementation 所需的工作跟踪、文档归属、领域资料和 Agent Notes 配置，补齐缺失项。

先读取项目指令、文档入口、工作项配置和实际引用，复用已有属主、路径、状态、格式及脚本定制。展示需要新增或调整的配置；本次授权补齐所选范围内的缺口，已有配置与资源不同的部分先报告，不直接覆盖。

确认首份新工作项和技术决定都有明确的属主、写入位置及规则入口。仅需要登记未来位置时，不创建空工件。对尚未确定的归属列出影响和待决事项。

本次不授权历史归档、属主迁移或记录格式升级。保留历史文件和项目工程推进规则，运行适用检查，报告修改、复用项与剩余缺口。
```

重复调用本身不会重置配置或升级资源。明确需要升级时，可在请求中追加：

```text
本次同时授权升级现有 Agent Notes 管理规则与工具。请逐文件比较资源版本和项目副本，提出并实施保留项目分类、路径、格式及脚本定制的合并；检查规则与工具兼容性。记录格式迁移、记录搬移或删除如确有需要，单独说明影响并等待专项授权。
```

逐文件处理规则见 [Agent Notes 配置与部署](../skills/user-invoked/setup-matt-pocock-skills/decision-records.md)。

## 已有项目：旧目录归档，新工作使用新属主

下面的提示词明确授权归属调整及必要的内容承接。这里的“归档”保留文件及原有位置，通过状态、适用范围和引用说明历史身份；仍需约束未来开发的内容先建立完整的新属主。归属切换顺序见 [登记规则](../skills/user-invoked/setup-matt-pocock-skills/artifact-registration.md)。

```text
/setup-matt-pocock-skills

请为当前已有项目切换文档归属，将旧 docs/specs/、docs/design/、docs/adr/ 作为归档资料保留，新工作使用配置好的工作项与 Agent Notes。本次授权调整文档权威、建立必要的新属主和修正状态及引用，不授权删除或搬移历史文件。

先检查项目指令、文档入口、Proposal/Issue 配置、历史 Spec/RFC/ADR、Agent Notes 及实际引用。展示“历史属主 → 新属主”的映射，逐项列出仍可能影响未来开发的合同或决定、处理结果、权威切换顺序和未决事项，再执行选择已明确的配置与记录更新。

- 仍应生效的技术设计或决定：在 Agent Note 中完整说明当前内容、适用范围、真实备选、理由和代价；复用已有相同决定的 Note。完成项目要求的评审后，让新属主成为该范围的唯一权威，旧文件作为历史来源引用。
- 仍应生效的产品合同：核对适用范围和新属主。本次交付行为归工作项；跨工作项持续生效的合同确需独立文档时，先登记新的属主与位置，再建立正文和替代关系。
- 已被取代或不再适用的内容：保留原文的历史价值，标明失效范围或现行属主。
- 是否继续生效尚不明确的内容：登记未决事项和影响；依赖它的新工作不得默认沿用旧工件，也不得无依据地补写决定。

新工作的范围、产品行为与验收、评审和批准证据由配置好的 Proposal/Issue 及跟踪器持有。长期技术提案、设计与决定由 Agent Notes 持有，工作项链接到 Note，同一决定不再新建 RFC 或 ADR。

先建立完整的新内容及所需评审，再撤销旧内容在对应范围的权威并修复活动引用。旧目录不接收无关新主题；文档入口明确归档范围和新工作去向，领域资料指引读取同一归属入口。禁止新旧两处同时拥有同一事实。

保留项目定制，按需合并配置，不以 setup 资源覆盖已有文件，不预建空目录或空记录。未完成新属主承接或评审的范围报告为未完成切换，不宣称全部归档生效。

最后运行适用检查，报告修改、归档范围、当前有效的新属主，以及尚未承接却会影响未来开发的合同或决定。本次配置不授权产品实现。
```

Note 的 `proposed/implemented/rejected` 表示交付生命周期，评审与批准证据归工作项。承接历史决定时按实际交付情况选状态；创建 Note 本身不证明决定已获批准或已交付。

## 只配置一部分能力

请求中点名所需范围即可。例如：

```text
/setup-matt-pocock-skills
本次只配置领域资料入口，复用现有文档归属和上下文布局，补齐必要指针；不部署工作跟踪、triage 或 Agent Notes。报告仍缺失且影响领域资料读取的配置。
```

多上下文项目需要分别确定领域边界与 Notes 记录范围。可在请求中补充“仅为 ordering 启用记录，暂不建立公共区”，其中名称应使用项目实际标识。多个上下文共用管理根下的一套 Notes 管理规则和工具，各记录范围按配置定位；新增项目不会自动加入。

## 配置完成后怎么确认和使用

检查 setup 报告，确认以下内容有明确结果：

- 项目管理根、指令入口和文档归属入口可以相互到达；从子项目读取也能定位同一登记。
- 所选跟踪器的工作项位置、状态及评审/批准证据规则完整；远程访问是否验证单独说明。
- 新工作和首份 Note 的位置可由配置确定；启用范围和分类足以创建记录，待定项说明影响。
- 原有定制及记录保留，历史切换说明具体完成范围和未决事项。
- 报告实际执行的检查及结果，缺少工具或凭据时列明未执行项。

采用默认 Notes 工具路径时，从目标项目管理根运行：

```sh
node scripts/decisions/check.mjs
node scripts/decisions/list.mjs
```

自定义安装使用项目登记的命令；上下文筛选等用法见 [Notes 工具说明](../skills/user-invoked/setup-matt-pocock-skills/resources/decision-records/scripts/decisions/README.md)。Node.js 不可用时，setup 应报告无法运行的检查。机械检查验证格式、配置和链接，决定内容与权威仍需按项目规则评审。

配置完成后，根据目标项目的工程推进规则开展工作。采用本仓库授权约定的项目，由用户另行发出 `/planning` 收敛范围和决定，或在工作充分定义后发出 `批准，执行实现`。setup 不自动创建产品提案、不发布 Issue 或标签，也不开始产品实现。
